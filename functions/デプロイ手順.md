# 受付（Firebase Functions）のデプロイ手順

`functions/index.js` を直したときは、**push だけでは反映されない。**
GitHub Pages が配るのはアプリ側（HTML/CSS/JS）だけで、受付は Google 側にあるため。
下のコマンドで別に上げる。

やるのは **Node が入っている端末**（担当k）。
アプリ側は触らないので、この作業で現場のアプリが止まることはない。

---

## 1回目だけ要るもの

Node.js（18以上）が入っていること。確認：

```bash
node -v
```

Firebase CLI を入れる：

```bash
npm install -g firebase-tools
```

Google アカウントでログイン（ブラウザが開く）：

```bash
firebase login
```

---

## 毎回やること

### ① 最新を取ってくる

```bash
git pull
```

### ② functions フォルダへ移動

```bash
cd mitsumori/functions
```

### ③ 必要なものを入れる（初回と package.json が変わったときだけ）

```bash
npm install
```

### ④ 上げる

```bash
firebase deploy --only functions:estimateFromPhotos --project mitsumori-35e9d
```

3〜5分かかる。最後に `Deploy complete!` と出れば成功。

## 上げたあと必ず確かめること

**「デプロイが成功した」と「アプリから呼べる」は別。** 一度これで踏みかけている。
下のページを開いて、実際に受付を叩く。

<https://nomurakougyouipad-oss.github.io/mitsumori/tools/test-ai.html>

工事の種類と一言を入れて「この文言で呼んでみる（写真なし）」を押す。
こう出れば直っている：

```
① 受付に届いた: はい（40秒前後）
② 相場が入っている項目:       13 / 13 件   ← 両方
③ よつばの単価が出せる項目:    6 /  6 件   ← 見ること
  → よつばの単価と相場が両方そろっています。
```

**②と③は必ず一緒に見ること。** 片方だけ見て直すと、もう片方が落ちても気づけない。
実際に2回やった（8/7 に相場が落ち、直したら 8/8 によつばの単価が落ちた）。

**※このページは実際にAIを呼ぶので1回数十円かかる。押しすぎないこと。**
上限は Anthropic 側で月 $10・通知 $5 に設定してある。

## うまくいかないとき

| 出るもの | 意味 | どうするか |
|---|---|---|
| `Error: Failed to get Firebase project` | プロジェクトが違う | `--project mitsumori-35e9d` が付いているか確認 |
| `HTTP Error: 403` | 権限が無い | そのGoogleアカウントが `mitsumori-35e9d` の編集者か確認 |
| `functions: command not found` | CLI が入っていない | 上の `npm install -g firebase-tools` |
| デプロイは通るのに相場が増えない | 上げたのが古いコード | `git pull` を先にやったか確認。`git log -1` で最新か見る |

## 2026/8/7 に何を直したか

**症状**: 概算の項目に「世の中の相場」が1件も出ない。全部「よつばの単価」だけ。

**調べた結果**（`tools/test-ai.html` と実データ）:

- 受付・App Check・画面はすべて正常だった
- AIは動いていた（直近4件のうち3件が `source:'ai'`・全項目 `未確定`）
- **AIが `marketAmount` を返したり返さなかったりしていた**
  （20項目中11件返した回と、16項目すべて null の回があった）

**原因**: 聞き方（`SYSTEM`）の

> 写真から読み取れないこと（寸法・型式・kW・数量）を推測で埋めないでください

が**相場にも効いていた**。加えて schema の説明が「分からなければ null」で、
null が楽な逃げ道になっていた。
寸法や型式は推測してはいけないが、**相場はもともと当てにいく数字**で性質が逆。

**直したこと**:

1. `SYSTEM` の禁止対象を「寸法・型式・kW・数量（＝ qty・cost・trade・persons・hours）」に限定
2. 「marketAmount は禁止の対象外。必ず入れる。null は例外」を足した
3. schema の `marketAmount` の説明から「分からなければ null」を外した

**この先ここを触るときの注意**: `marketAmount` の説明に
「分からなければ null」と書き戻さないこと。それがこの症状の元。

## 2026/8/8 に何を直したか（上の直しが起こした逆の症状）

**症状**: 相場は出るようになったが、今度は**よつばの単価が消えた**。
配管工事／一言「ステンレス・40A配管・60m」で再現。直す前は出ていた。

**原因**: 上の直しの①で、`SYSTEM` の禁止リストに
`qty・cost・trade・persons・hours` と書いた。**`trade・persons・hours` が余計だった。**
よつばの単価はこの3つから出る（`js/rough-calc.js` の `yotsubaBase`）。
相場を強めたぶん、人工が禁止側に寄って null で返るようになった。

**人工の見立ては推測ではない。** アプリが毎回聞いている①②そのもの。
禁止してよいのは **数量（qty）と よつばの仕入れ値（cost）だけ**。

**直したこと**:

1. `SYSTEM` を書き直し、**よつばの単価と相場を「2つで1組」として同じ強さで**必ず入れさせた
2. 禁止は `qty` と `cost` だけに絞った。`cost` は受付側でも `null` に上書きする
   （AIには分からない数字なので、作り話が「よつばの単価」の顔で出るのを止める）
3. 職種名を `settings/unitRates` から読んで聞くときに渡す
   （単価表に無い名前を返されると、単価が引けず金額が黙って消えるため）
4. 返ってきたものを受付が数え（`coverageOf`）、欠けていたら**1回だけ聞き直す**（`fillGaps`）。
   写真は送らないので安い。埋めるのは空いている欄だけで、入っている値は触らない
5. それでも片方だけが残ったら、件数を返して**画面の帯とトーストに出す**（芯4）

**この先ここを触るときの注意**: **片方を強めるときは、もう片方も同じ強さで書く。**
`tools/test-ai.html` は②相場と③よつばの単価を必ず並べて出す。片方だけ見て直さない。
